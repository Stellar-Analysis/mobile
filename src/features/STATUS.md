# Feature module status

`src/features/` holds one folder per native-capability integration. Folder existence does **not** mean the feature works — completeness ranges from fully tested modules to near-empty placeholders. This table was generated by checking, per module: lines of non-test `.ts`/`.tsx` source, presence of a `__tests__` directory, and presence of a `README.md`. Regenerate it (`find src/features/*/ ...`) if a module changes tier — don't hand-edit stale entries.

## Using this table

- Building a screen that depends on one of these? Check its tier first. Tier 4/5 modules should be treated as "needs to be built," not "needs a bugfix."
- Picking up a Tier 3 module to finish? Add a `__tests__` directory and a `README.md` before calling it done, and move it to Tier 1 or 2 in this file.
- This file exists because a repo-wide documentation audit found the previous state — a large number of feature folders with no indication of which ones actually worked — was itself a source of confusion (see `Stellar-Analysis/mobile` commit history around the `HACKMD-README.md` write-up).
